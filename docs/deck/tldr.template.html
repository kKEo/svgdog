SVGDog

Diagrams as code, checked like code.

  • One binary that draws an SVG from a short YAML spec
  • Checks any SVG against 38 rules, and fixes what it safely can
  • No network, and the same output on every run

Press the right arrow key, or swipe, to start.

Diagrams rot, and nobody notices.

  • Hand-drawn SVGs overflow their boxes, clip at the edge and fail contrast checks.
  • A picture in your docs can't be diffed, reviewed or regenerated.
  • An AI agent can write SVG, but it can't see what it drew.

Describe the diagram in YAML. SVGDog draws it, checks it and tells you exactly what is wrong.

The whole loop fits in four commands.

  1. svgdog schema spec                       # learn the spec format, once
  2. svgdog render orders.yaml -o orders.svg  # compile and check in one call
  3. svgdog fix orders.svg --in-place         # apply the safe fixes findings carry
  4. svgdog preview orders.svg -o orders.png --annotate

Repeat until the exit code is 0. preview writes a PNG file you can open; it doesn't start a server.

A spec says what, not where.

version: 1
diagram: flow
title: Order placement
direction: right

nodes:
  - id: api
    label: Order API
    kind: service
    emphasis: true
  # … web, db and queue

groups:
  - id: backend
    label: Backend
    members: [api, db, queue]

edges:
  - from: api
    to: queue
    label: publish
    style: async
  # … two more edges

Excerpt of tests/fixtures/orders.yaml. SVGDog places nodes on an 8 px grid and routes the connectors around the boxes.

Four diagram types.

flow

Nodes and connectors, left to right or top down.

layers

Top-level groups become stacked bands.

sequence

Lifelines, with messages from top to bottom.

free

You pin each node with at: [x, y].

Three profiles set how strict to be: minimal, docs and strict. Silence a single element with an svgdog-disable comment that gives a reason.

Change one thing, or fix what the checker found.

svgdog edit orders.yaml \
  --set '#api.label=Orders service' \
  --in-place

On a spec, edit patches the YAML text so your comments survive, then re-renders and reports findings. On an SVG, it changes only the elements you target.

svgdog fix broken.svg --in-place
svgdog fix broken.svg --dry-run

--dry-run shows the diff first. Each finding says whether it carries a fix. --unsafe adds fixes that move or recolour content. Writes are atomic.

Agents get the same tools over MCP.

svgdog mcp --root ./docs

A stdio server. Every path stays inside --root. Ask for a preview without an output file and the PNG comes back as image content, so the agent can look at what it drew.

Built to be boring in CI.

Offline

Fonts are compiled in. No network, browser or language runtime is needed.

Deterministic

Golden files are compared byte for byte, so the same spec gives the same SVG.

Cross-platform

The CI workflow is configured to run clippy and the full test suite on Linux, macOS and Windows.

Install today with cargo build --release. The release workflow for prebuilt binaries is in place, but no release is published yet.
